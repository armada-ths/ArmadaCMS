# Photo events rollout

The guest app is part of `armada.nu` and the API/admin/worker are part of ArmadaCMS. No separate Vercel project is needed.

1. Approve the privacy notice, legal basis and retention procedure. Create each event with an HTTPS privacy URL. The API will not activate an event without a valid privacy URL. The CMS has no review schedule or automatic deletion date. An administrator manually requests deletion when the photos are no longer needed.
2. Apply the existing `20260925135808_photo_events.sql` to the appropriate Supabase environment. It includes the event/photo/export tables and explicit deletion status in the same unapplied migration; no separate retention migration is needed. Do not grant anonymous Storage policies.
   Verify that the Supabase project's global Storage file-size limit is larger than the expected full-event ZIP. A per-bucket setting cannot exceed the global limit; the Free-plan ceiling is 50 MB, which is not enough for a 3,000-photo export.
3. Configure `PHOTO_TOKEN_SECRET` (at least 32 random bytes) in the GCP Secret Manager environment. Keep its value stable across API instances and worker executions; changing it invalidates all existing event links and guest hashes. Configure the public reCAPTCHA site key in the Vercel frontend, and enable the reCAPTCHA Enterprise API and the runtime IAM role in GCP. Do not put the token secret in the frontend.
4. Apply the Supabase Terraform output changes, then the GCP Terraform changes before the next ArmadaCMS deployment. Terraform grants Cloud Build Cloud Run Developer on this Job only. Each successful backend deployment updates both the Cloud Run service and `-photo-worker` Job to the same image; a failed Job update fails the deployment. Confirm both image revisions after deployment. The Job must have access to the same database and private buckets; Cloud Scheduler executes it every 15 minutes.
5. Deploy `armada.nu`, then add `photos.armada.nu` to the existing `armada-nu` Vercel project. Configure the CNAME value Vercel shows in the external DNS provider; allow Vercel to provision TLS. DNS is intentionally not managed by this Terraform root.
6. In ArmadaCMS create a disabled test event, add the privacy URL, activate it, and copy its link or QR code. On an iPhone and Android, grant camera access, capture a new photo in the guest page, and verify that there is no file picker. Moderate the pending photo and verify that it appears in both the grid and an open slideshow within one minute while the page remains visible. Start a ZIP export and verify the signed admin download. In a disposable event, request deletion and confirm that the worker removes photos and exports. Check THS-controlled marketing copies separately.

The guest link is a bearer capability: anyone with it can view approved pictures during the gallery window. QR rotation invalidates previous links. Public API request logging omits token-bearing paths. Signed media URLs remain visible to recipients and are valid for approximately one hour; the frontend renews loaded links after 50 minutes. The visible gallery polls for newly approved photos every 30 seconds and refreshes immediately when the tab becomes visible again. Browser background throttling and network delays can extend the interval. The standard guest UI captures images from a live camera stream, encodes them as JPEG and exposes no file picker. The API accepts only JPEG signatures and re-encodes accepted images without metadata. Browsers cannot attest that an API client used a real-time camera capture, so this is a user-interface restriction rather than a server-enforced authenticity guarantee.

No production migration, Terraform apply, Vercel domain, DNS change or event activation should happen before the privacy notice and the responsible Armada operator are ready to approve the rollout.
