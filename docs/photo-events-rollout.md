# Photo events rollout (delete after launch)

The guest app is part of `armada.nu` and the API/admin/worker are part of ArmadaCMS. No separate Vercel project is needed.

CMS event links and QR codes use `PHOTO_APP_BASE_URL`. Terraform sets it to `https://staging.armada.nu/photos` in staging and `https://photos.armada.nu` in production. Local Docker Compose uses `http://localhost:3000/photos`. Keep each frontend's API URL pointed at the matching CMS environment; a staging QR code should never lead to the production photo host.

Cloud Vision SafeSearch auto-approval is optional per event and off by default. Confirm that the forward `photo_vision_safe_search` migration has been applied by the Supabase GitHub integration before deploying the backend; checked-in SQL migrations own the schema in local, staging, and production environments. Terraform enables `vision.googleapis.com` in both GCP environments. The Cloud Run service uses its existing runtime identity and sends a temporary 640-pixel JPEG copy inline to Vision; no Vision API key, GCS object access, or extra Cloud Run job is needed. Update and approve the guest privacy notice before enabling auto-approval on a live event. SafeSearch checks only explicit-content likelihoods, not consent, event relevance, or marketing suitability. All five categories must be `UNLIKELY` or `VERY_UNLIKELY` for automatic publication. Any other result or service error stays pending for manual review. The guest gallery's existing 30-second refresh picks up automatic approvals. Existing pending photos are not reprocessed.

1. Approve the hard-coded privacy notice, legal basis and retention procedure before enabling a live event. The guest page always links to `/photos/privacy`; no per-event privacy URL is configured in the CMS. The CMS has no review schedule or automatic deletion date. An administrator manually requests deletion when the photos are no longer needed.
2. Confirm that the Supabase GitHub integration has applied `20260925135808_photo_events.sql` to the appropriate environment before deploying the API. It includes the event/photo/export tables and explicit deletion status; no separate retention migration is needed. Do not grant anonymous Storage policies.
   Verify that the Supabase project's global Storage file-size limit is larger than the expected full-event ZIP. A per-bucket setting cannot exceed the global limit; the Free-plan ceiling is 50 MB, which is not enough for a 3,000-photo export.
3. Configure `PHOTO_TOKEN_SECRET` (at least 32 random bytes) in the GCP Secret Manager environment. Keep its value stable across API instances and worker executions; changing it invalidates all existing event links and guest hashes. Configure the public reCAPTCHA site key in the Vercel frontend, and enable the reCAPTCHA Enterprise API and the runtime IAM role in GCP. Do not put the token secret in the frontend.
4. Apply the Supabase Terraform output changes, then the GCP Terraform changes before the next ArmadaCMS deployment. Terraform grants Cloud Build Cloud Run Developer on this Job only. Each successful backend deployment updates both the Cloud Run service and `-photo-worker` Job to the same image; a failed Job update fails the deployment. Confirm both image revisions after deployment. The Job must have access to the same database and private buckets. Export and deletion requests launch it immediately; Cloud Scheduler also executes it at the start of every hour to retry queued work and remove expired exports. Scheduled retries and cleanup may therefore take up to one hour.
5. Deploy `armada.nu`, then add `photos.armada.nu` to the existing `armada-nu` Vercel project. Configure the CNAME value Vercel shows in the external DNS provider; allow Vercel to provision TLS. DNS is intentionally not managed by this Terraform root.
6. In ArmadaCMS create a test event with appropriate upload and gallery times, then copy its link or QR code. On an iPhone and Android, open the native camera from the guest page, capture and confirm several photos one at a time, remove one staged photo with its cross icon, then upload the remaining photos with one button press. Test JPEG and HEIC where supported. Moderate the pending photos and verify that they appear in both the grid and an open slideshow within one minute while the page remains visible. Start a ZIP export and verify the signed admin download. In a disposable event, request deletion and confirm that the worker removes photos and exports. Check THS-controlled marketing copies separately.

The guest link is a bearer capability: anyone with it can view approved pictures during the gallery window. QR rotation invalidates previous links. Public API request logging omits token-bearing paths. Signed media URLs remain visible to recipients and are valid for approximately one hour; the frontend renews loaded links after 50 minutes. The visible gallery polls for newly approved photos every 30 seconds and refreshes immediately when the tab becomes visible again. Browser background throttling and network delays can extend the interval. The guest UI requests native camera capture through the HTML `capture` attribute, retains each capture in a local staging list, and uploads the staged photos only after a separate button press. Each photo is still sent in its own API request, with at most two requests in flight. The API accepts JPEG, PNG, WebP, and HEIC/HEIF signatures and re-encodes accepted images as metadata-free JPEGs. A browser may still offer existing files, and the API cannot prove that an image was taken at that moment; camera-only capture is a user-interface preference rather than an authenticity guarantee.

For local development, `scripts/dev-up.ps1` starts Supabase Postgres and Storage; its SQL migrations create the public and private photo buckets. Docker Compose sets `PHOTO_RECAPTCHA_BYPASS_LOCAL=true`, `PHOTO_VISION_MOCK_RESULT=safe`, a local-only photo token secret, and a browser-reachable Supabase S3 presign endpoint on the API. The guest frontend skips reCAPTCHA only in a development build pointed at a localhost API, so no site key or Google credentials are needed for local photo uploads. Set the Vision mock to `review` or `error` to test manual fallback. When running the Go API outside Docker, set these variables explicitly for the local process. Both local shortcuts are ignored on Cloud Run (`K_SERVICE` is set); staging and production require real Google assessments.

No production migration, Terraform apply, Vercel domain, DNS change or event activation should happen before the privacy notice and the responsible Armada operator are ready to approve the rollout.
